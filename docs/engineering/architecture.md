# Architecture

State after the Phase 3 build (2026-11-11). One Next.js 16 app (App Router) with Payload 3.93 mounted inside it, deployed on Vercel. Data lives in Neon Postgres, files in Vercel Blob. Stack decision: [ADR-0001](decisions/ADR-0001-stack-nextjs-payload-vercel.md).

## Route groups

The app has **two root layouts**:

| Group | Root layout | Routes |
|---|---|---|
| `src/app/(frontend)/` | `layout.tsx`: tokens, fonts, accent, default metadata | `/` (temporary Home placeholder until P4), `/portfolio`, `/portfolio/[collection]`, `/portfolio/[collection]/[project]`, `/journal`, `/journal/page/[n]`, `/journal/[slug]`, `/book` (with the `submitInquiry` server action), `/next/preview` (draft mode), `not-found.tsx`, `[...slug]` (sends unmatched URLs to the 404 with HTTP 404) |
| `src/app/(payload)/` | generated by Payload | `/admin/*` (the Studio), `/api/*` (REST) |

- Static segments (`/admin`, `/api`, real pages) always win over the `[...slug]` catch-all.
- GraphQL is disabled in the Payload config and its routes are removed; `/api/graphql` returns 404.
- The REST API serves the Studio only. Public pages never call it.
- Build output: `/portfolio`, `/journal` and `/book` are static (○); collection, project, journal list (`/journal/page/[n]`, pages 2 and on) and journal entry pages are prerendered from `generateStaticParams` (●); `/next/preview` is a dynamic route handler (ƒ). Slugs and page numbers not generated at build render on demand (a page, a 308 or a 404), and Next caches the result.
- Journal pages use path URLs, not `?page=N`, so every list page stays static ([ADR-0005](decisions/ADR-0005-journal-paths-and-refresh-scope.md)). A post slugged `page` still resolves at `/journal/page` through `[slug]`.

## Content model

| Slug | Kind | Notes | Admin group |
|---|---|---|---|
| `users` | auth collection | `name`; lockout after 5 failures for 15 min; every operation requires a logged-in editor | Admin |
| `media` | upload collection | JPEG/PNG/WebP up to 25 MB, `alt` required, `caption`, `credit`, focal point, 4 WebP sizes; public read | Library |
| `site-settings` | global | identity, socials, accent, labels, default SEO; versions on, drafts off; public read | Settings |
| `disciplines` (Studio: "Collections") | collection | name, slug, `order`, intro, `openerTint`, `layout` (`projects`/`list`), highlights, aspects, finale copy, SEO `meta`, hidden `previousSlugs`; no drafts; public read | Portfolio |
| `projects` | collection | Build Spec fields, `story` blocks, credits, sidebar fields, SEO `meta`, hidden `previousSlugs`; drafts + autosave + versions; **published-only** read for anonymous users | Portfolio |
| `posts` | collection | title, excerpt, cover, `story` (required), SEO `meta`; sidebar `category` (required), `publishedAt` (filled on first publish when empty), `relatedProjects`, slug, hidden `previousSlugs`; drafts + autosave + versions; **published-only** read for anonymous users | Journal |
| `categories` | collection | name, slug (no `previousSlugs`: no pages of their own); no drafts; public read; can't be deleted while a post uses it | Journal |
| `inquiries` | collection | name, email, `projectType` (text: the label the visitor picked), timing, message (all read-only in the Studio); sidebar `status` (`new`/`replied`/`archived`, any to any), private `notes`, `createdAt` labelled "Received"; no drafts or versions; read/update/delete editor only, **create denied to everyone** (the server action and seed write with `overrideAccess`); Duplicate off | Inbox |

- Story blocks (`src/blocks/story.ts`): `chapter`, `text` (Lexical: paragraphs, bold, italic, lists, custom-URL links), `image`, `gallery`, `video`, `quote`. `posts` reuse them unchanged (the blocks set `interfaceName`, so `Post['story']` and `Project['story']` share types).
- Shared slug fields (`src/fields/slug.ts`): Payload `slugField` with an ASCII `toSlug`, a format validator and a fill-on-create hook, plus the hidden `previousSlugs` list (left out with `{ previousSlugs: false }`).
- The SEO plugin wraps the main fields in a "Content" tab and adds an "SEO" tab; sidebar fields stay top-level.
- Access helpers live in `src/access/` (`authenticated`, `anyone`, `publishedOnly`). Schema changes ship as migrations in `src/migrations/`.

## Data flow

**Public reads**
- Public pages are **server components** that read through Payload's Local API, in-process, with access applied (`overrideAccess: false`, `draft: false`).
- `src/lib/getSiteSettings.ts`, `src/lib/portfolio.ts` and `src/lib/journal.ts` wrap the reads in React `cache`. Journal lists read 10 posts per page, sorted `-publishedAt` then `-id`.

**Refresh on publish** (`src/hooks/`)
- Pages are **statically rendered** and refreshed on demand with `revalidatePath`, never by a redeploy.
- Hooks act only when what the public sees changes. Project and post hooks snapshot the **main row** (the last published state; draft and autosave saves only write versions) before a save and compare it afterwards ([ADR-0004](decisions/ADR-0004-slug-redirects-and-publish-hooks.md)). Both are built by one factory, `src/hooks/publishHooks.ts`.

  | When this changes | Refresh |
  |---|---|
  | `site-settings` | every page (`revalidatePath('/', 'layout')`) |
  | a project's published state (publish, unpublish, rename, move, delete) | its old and new project URLs, both collection pages, and `/` when `showOnHome` is on now or was before |
  | a discipline (any save or delete) | every page, because project pages show its name and use its slug |
  | a project's published state (as above) | also every journal entry, by route pattern, so "See the work" links stay right |
  | a post's published state (publish, unpublish, rename, delete) | its old and new entry URLs, `/journal`, every `/journal/page/N` (by route pattern) and `/` |
  | a category (any save or delete) | every page, because entries and lists show its name |

- "Every page of a dynamic route" is `revalidatePath(pattern, 'page')` with the route **file** as the pattern, route group included (`'/(frontend)/journal/[slug]'`): Next tags pages by file path and does not strip groups ([ADR-0005](decisions/ADR-0005-journal-paths-and-refresh-scope.md)). The patterns live in `src/lib/publishing.ts`.
- Deleting a category that any post uses is refused (`src/hooks/categoryHooks.ts`): the database would otherwise set those posts' required category to null.

- Seeds and scripts skip all of this with `context.disableRevalidate`; refresh failures are logged, never thrown.

**Slug redirects** (owner decision; [ADR-0004](decisions/ADR-0004-slug-redirects-and-publish-hooks.md))
- When a slug change is published, the old slug is appended to the doc's `previousSlugs`.
- A request for an unknown collection slug looks it up there and 308s to the current URL.
- A project is found by its slug alone (unique across projects), else by a previous slug. Any URL that isn't the canonical `/portfolio/<collection>/<project>` 308s there in one hop.
- A post is found by its slug, else by a previous slug, and an old `/journal/<slug>` 308s to the current one.

**Draft mode and live preview**
- `/next/preview` enables Next.js draft mode only with `PREVIEW_SECRET`, an editor session and a site-relative path; otherwise 403.
- The project and journal entry pages read drafts only when draft mode is on **and** the editor session checks out at render time (`src/lib/draftEditor.ts`); they then mount `LivePreviewListener` (`RefreshRouteOnSave`). List pages always show published posts only.
- The Studio's live preview pane and "Preview" button use a relative `/next/preview?…` URL, so Payload's `serverURL` stays unset. Projects and posts share the breakpoints (`LIVE_PREVIEW_BREAKPOINTS` in `src/lib/preview.ts`).

**Book Me inquiries** ([ADR-0006](decisions/ADR-0006-inquiry-submission.md))
1. `/book` is static. `InquiryForm` (a client island) posts with `useActionState` to the `submitInquiry` server action (`src/app/(frontend)/book/actions.ts`); without JavaScript the same form posts and the page re-renders with the result.
2. `validateInquiry` (`src/lib/inquiry.ts`): a filled honeypot (`website`) is spam; then the Build Spec field rules and messages; then, for otherwise valid input, `elapsedMs` (set by the form on submit) under 3,000 is spam. Spam answers `sent` and saves nothing.
3. Valid input: `payload.create` on `inquiries` with only the five form fields and `status: 'new'`, `overrideAccess: true`. A Payload validation error maps back to the field messages; any other error answers `failed` with the visitor's values.
4. After the create returns: `payload.sendEmail` with the plain-text alert (`buildInquiryAlert`) to `site-settings.contactEmail`, reply-to the visitor, bounded at 5 s. Failures are logged with the inquiry ID and error name/status only, never retried; the visitor still gets `sent`.
5. Discipline saves already refresh every page, so the project-type options on `/book` stay current. Studio edits to inquiries refresh nothing (they have no public page).

**Email**
- `@payloadcms/email-resend` is Payload's adapter when `RESEND_API_KEY` is set (otherwise emails are logged to the console). It also sends Payload's password-reset emails. From address: `EMAIL_FROM_ADDRESS`, else Resend's test sender until P7.
- Link base URL for emails (`adminBaseUrl`): `NEXT_PUBLIC_SERVER_URL`, else the Vercel branch or deployment URL, else `http://localhost:3000`.

**Accent**
- The root layout sets `--gold` on `<html>` to the token for `site-settings.accent` (`src/lib/accent.ts`); components read it through `--color-booking`.

## Media pipeline

1. In the Studio, the browser uploads the file **straight to Blob** (`clientUploads`), bypassing Vercel's 4.5 MB request limit. The app issues a signed receipt; the file lands under `<prefix>/<objectKey>/<filename>`.
2. On save, Payload downloads the object and checks it:
   - its real type, from the bytes (JPEG/PNG/WebP only);
   - its real size, through the `beforeOperation` hook in `src/lib/media/uploadLimit.ts` (25 MB).
3. Payload generates four WebP sizes next to the original, named `<original>-<size>.webp` (`thumb` 480, `card` 960, `feature` 1600, `hero` 2560 px). `withoutEnlargement: true` means every size always exists.
4. Media URLs point **directly at Blob** (`disablePayloadAccessControl`). The Studio thumbnail is the Blob `thumb` URL.
5. On the site, `MediaImage` renders `next/image` with the custom loader (`src/lib/media/imageLoader.ts`), which rewrites the original's URL to the nearest size. `deviceSizes` are exactly the four sizes; `/_next/image` is never used. The focal point drives `object-position`.

## Front end

| Path | Contents |
|---|---|
| `src/styles/tokens.css` | Canonical design tokens (`@primitive` / `@semantic`) and the focus ring. Specs in `docs/design/` |
| `src/styles/globals.css` | Minimal reset and base type |
| `src/components/ui/` | `Button` (pill buttons and text links), `MediaImage` |
| `src/components/site/` | `SiteHeader`, `SiteFooter`, `Wordmark`, `LensMark`, `ChapterOpener`, `ChapterHeading`, `BookingFinale`, `DetailsStrip`, `Filmstrip`, `CollectionTile`, `ProjectCard`, `PieceRow`, `RevealMore`, `JournalRow`, `Pagination`, `JournalEntryFooter`, `GoodToKnow`, `InquiryForm`, `navItems` |
| `src/components/story/` | `StoryBlocks` (one renderer per block), `VideoEmbed`, `LivePreviewListener` |
| `src/lib/` | `portfolio.ts` and `journal.ts` (public reads), `inquiry.ts` (form validation, alert message, email link base), `seo.ts` (metadata), `publishing.ts` (paths, route patterns, previous slugs, `publishedAt` fill), `date.ts` (Singapore dates), `draftEditor.ts`, `preview.ts`, `video.ts`, `safeHref.ts`, `slug.ts`, `openerTint.ts` |
| `src/copy.ts` | All non-CMS text |

Components are server components except four client islands:
- `RevealMore` ("More projects": reveals pre-rendered cards, no fetch);
- `VideoEmbed` (loads the provider iframe on click);
- `LivePreviewListener` (draft mode only);
- `InquiryForm` (Book Me: pending state, focus management and the elapsed-time spam check; works without JavaScript).
