# Creative Portfolio

A personal portfolio site for a multidisciplinary creative, with its own CMS (the "Studio"). The work is shown in four collections: **Photography**, **Film & Video**, **Design & Illustration** and **Writing & More**. The site's main job is to turn interest into **Book Me** inquiries. The journal is a secondary path.

> **Status: Phase 0 (Foundation) done.** The app shell, database, media, site settings, header, footer and 404 run on Vercel previews. Next: P1 Portfolio. See the [roadmap](#roadmap) and [`docs/engineering/dev-workflow.md`](docs/engineering/dev-workflow.md) to run it.

## What gets built

**Public site**:
- Home, Portfolio, a page per collection and per project;
- About, Journal and individual journal entries;
- Book Me and a 404 page;
- a generated `sitemap.xml` and `robots.txt`.

**Studio** (the Payload admin at `/admin`): the owner edits everything here.
- Projects, collections, journal posts, inquiries, media, and the site-wide settings plus the Home and About page content.
- Drafts, live preview and version history.
- An inquiries inbox.

**Inquiries**:
- Each Book Me submission is saved in the Studio.
- An email alert goes to the owner, who can reply to it directly.

## How work happens

Each phase follows the same loop, using the Pi workflow:

1. **Resolve.** Answer the phase's blocking open questions.
2. **Plan.** `/pi-plan` turns the phase spec into a task plan against the current code.
3. **Build.** `/pi-build` works through the plan one task at a time. Each task is verified and committed before the next starts.
4. **Close.** When the Definition of Done passes, set the spec's status to `Done`.

## Out of scope at launch

From the Build Spec:
- private or password-protected client galleries;
- prints, a shop or any payments;
- online booking or availability calendars;
- multiple editor roles, translations, journal comments or a newsletter;
- uploading or hosting video files. Video is embedded from Vimeo or YouTube only.
